# nurture-bloom-mvp — 需求规格

## 目标

在 Better-T-Stack 基础上构建一个移动端优先的“育爱成长”MVP，以 Stitch 提供的 Nurture & Bloom UI 为视觉基底，并把课程里的全栈能力逐步接入真实产品。

## 用户故事

- 作为父母，我想查看宝宝的成长概览，以便快速了解最近状态。
- 作为父母，我想记录成长瞬间，以便持续保存家庭记忆。
- 作为父母，我想搜索育儿百科，以便快速找到可信的科普内容。
- 作为学习者，我想通过真实页面逐步接入 API、数据库和 GitHub 集成，以便把学习笔记转化为可运行实践。

## 功能需求

1. 提供成长首页、时光记录、育儿百科和个人中心四个主要入口。
2. 使用 Stitch 的设计语言：暖奶油背景、橙色主色、柔和圆角、Quicksand 字体、环境阴影和移动端底部导航。
3. 把重复视觉模式抽取为可复用 Tailwind UI 组件和全局设计 token。
4. 先以本地演示数据完成可操作页面，再接入类型安全 API 和数据库。
5. 预留 Hono、Drizzle、GitHub API 和 AWS SAM 的渐进式接入边界。
6. 页面在 390px 移动宽度下可用，桌面端保持居中和可读。
7. 不提交密钥、真实医疗隐私或真实用户数据。

## 验收标准

- [ ] Better-T-Stack 项目可以安装、开发、构建和测试。
- [ ] Stitch 视觉基底在主要页面中得到还原，且公共样式没有重复散落。
- [ ] 四个主入口可以导航，空状态、加载状态和错误状态可理解。
- [ ] 至少一个成长记录闭环可用。
- [ ] 至少一个 Hono API 和一个 Drizzle 数据模型接入产品。
- [ ] GitHub API 与 AWS SAM 作为后续可验证的课程增强点保留清晰边界。
- [ ] 通过项目测试、构建和移动端关键路径验证。
