# 育爱成长（Nurture & Bloom）MVP PRD

## 1. 项目概述

“育爱成长”是一款移动端优先的宝宝成长记录与育儿知识应用。首版以 Stitch 提供的 Nurture & Bloom UI 为视觉基底，使用 Better-T-Stack 构建可运行的全栈学习项目，并把课程学习笔记中的方法逐步落到真实功能中。

项目不是一次性完成所有云服务，而是采用“先做出产品，再逐步接入工程能力”的学习路径：先完成 UI 和交互，再接入类型安全 API、Drizzle 数据库、GitHub API，最后再进入 AWS SAM 部署实践。

## 2. 目标

### 产品目标

- 让家长可以快速查看宝宝的成长状态。
- 让家长可以记录和回顾成长瞬间。
- 让家长可以按主题搜索育儿科普内容。
- 用温暖、低压力的视觉风格建立持续记录的意愿。

### 学习目标

- 通过一个真实产品掌握 Better-T-Stack 的项目组织方式。
- 理解 Tailwind 设计 token 和可复用组件的边界。
- 实践 React 页面、类型安全 API、Hono 和 Drizzle 的协作关系。
- 将 GitHub API、AWS SAM 等课程内容作为后续可验证的里程碑接入。
- 每个阶段都保留运行命令、测试证据和学习记录。

## 3. 目标用户

- 需要记录宝宝日常成长的父母或家庭成员。
- 希望通过完整项目学习现代全栈开发的学习者。

## 4. 首版范围

### 4.1 成长首页

- 展示宝宝问候语和基本资料。
- 展示身高、体重等成长指标卡片。
- 展示已完成和待完成的成长里程碑。
- 展示近期疫苗提醒。
- 展示今日成长记录。

### 4.2 时光记录

- 按时间展示成长记录。
- 支持记录标题、日期、心情、正文和标签。
- 提供新增记录入口。
- 首版允许使用本地演示数据或本地持久化数据。

### 4.3 育儿百科

- 展示精选文章和育儿主题分类。
- 支持按关键词搜索。
- 覆盖喂养、护理、疫苗、早教等基础主题。
- 健康内容必须带有科普免责声明。

### 4.4 我的

- 展示宝宝资料摘要。
- 展示设置和数据概览入口。
- 预留 GitHub 用户信息实践入口。

## 5. 视觉与交互要求

- 使用 Stitch 素材和 `DESIGN.md` 中的设计规范。
- 采用暖奶油色背景、白色卡片、橙色主色、蓝色和薄荷绿色辅助色。
- 使用 Quicksand 和中文系统字体。
- 使用 8px 间距基线、16–32px 圆角、柔和环境阴影。
- 页面采用移动端优先布局，在 390px 宽度下不出现横向溢出。
- 使用顶部栏和底部导航作为统一应用壳。
- 按钮、卡片、标签、指标卡、搜索框、空状态和错误状态应可复用。
- 主要操作必须有明确的 hover、focus、disabled 和错误反馈。

## 6. 技术要求

- 项目目录：`/Users/shier/Desktop/course-homework`
- 使用 Better-T-Stack 作为项目基础。
- 使用 TypeScript。
- 使用 Tailwind CSS，并集中维护全局设计 token 和基础样式。
- 使用项目默认的类型安全客户端/服务端通信方式。
- 使用 Hono 作为服务端 API 边界。
- 使用 Drizzle 作为数据库访问层。
- 本地开发优先使用轻量数据库配置，具体方案由 TC Flow 在 Contract 阶段确定。
- 页面不直接依赖数据库 SDK，统一通过服务层或 repository 访问数据。
- 不提交 API Key、Token、密码、完整支付信息或真实用户隐私。

## 7. 学习里程碑

1. **UI 复刻**：从 Stitch HTML/CSS 提取设计 token、全局样式和组件。
2. **产品交互**：完成四个主页面、导航、搜索、空状态和记录交互。
3. **类型安全 API**：将至少一个页面从本地演示数据切换到 Hono API。
4. **数据库实践**：使用 Drizzle 建立成长记录或宝宝资料模型并完成最小 CRUD。
5. **GitHub API**：在“我的”页面接入 GitHub 用户信息查询表单。
6. **AWS SAM**：把 API 迁移到 Lambda/API Gateway，记录部署与权限边界。

## 8. 非目标

- 首轮不实现完整账号体系和复杂权限模型。
- 首轮不实现医疗诊断或个性化医疗建议。
- 首轮不要求真实云端媒体存储。
- 首轮不要求生产环境部署。
- 首轮不要求 AI、RAG、Agent 和 3D 功能。

## 9. 验收标准

- 可以安装依赖、启动开发环境并完成生产构建。
- Stitch 视觉基底在四个主入口中保持一致。
- 公共视觉规则和重复交互已抽取为可复用组件。
- 390px 宽度下页面可用，无主要内容溢出或底部导航遮挡。
- 至少一个成长记录流程可以完成新增或读取闭环。
- 至少一个 API 和一个 Drizzle 数据模型可运行并有验证命令。
- 测试、构建和关键页面验证通过。
- 文档记录当前完成的学习里程碑、运行命令和已知限制。

## 10. 风险与约束

- Stitch 中的外部图片 URL 可能失效，必要时由实现阶段替换为本地占位资产。
- AWS 账号和凭据未准备好时，只完成本地 API 与部署配置，不阻塞 UI 和数据库学习。
- 育儿百科内容只能作为科普，不替代医生建议。
- 外部 Review 只发送脱敏后的 Diff，不发送本地路径、密钥或真实隐私数据。
