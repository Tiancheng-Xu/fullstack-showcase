# 线上页面产品化表达设计

**日期：** 2026-08-03  
**状态：** 已确认  
**适用范围：** `course-homework` 仓库中所有会进入线上构建并呈现给访客的页面元素与公开导航链接

## 目标

仓库中的功能来自真实线上项目，部分页面同时承担学习实践用途。面向面试官和产品访客时，页面应以真实产品、工程案例和测试网原型的身份呈现，不暴露“学生提交物”语境。

本次改动只处理用户能够在浏览器中看到或访问的内容。内部学习记录继续保留原有表达，确保实现过程、课程要求和验收证据仍可追溯。

## 范围边界

### 必须调整

- React 渲染出的标题、正文、按钮辅助文案、无障碍标签和页脚说明。
- 页面导航中显示给用户的项目名称。
- 公开 URL 中的 `homework` 路径，以及指向该路径的站内链接。
- 与上述展示内容直接对应的组件测试、路由测试和快照断言。

### 保持不变

- `HOMEWORKS.md`、`docs/qa`、`docs/superpowers` 和其他内部学习记录。
- `homeworks/` 目录、包名、依赖别名和已有 Git 历史。
- 仅开发者可见的组件名、CSS 类名和源文件名，例如 `CourseEvidenceFooter` 和 `.course-evidence`。
- Sepolia、测试网、概念验证、隐私风险、公开交易和不可兑换等真实产品边界。

## 全仓覆盖矩阵

2026-08-03 的仓库盘点确认只有两个独立的线上前端构建入口：

| 线上构建 | 覆盖页面 | 本次处理 |
|---|---|---|
| `apps/web` | 育爱成长主站、GitHub Profile、成长记录、时光、指南、个人页 | 清理全部公开路由与可见元素；迁移 GitHub Profile 公开地址 |
| `homeworks/06-web3-dapp/web` | BabySteps · 成长星球 | 清理 Hero、钱包、便签和技术能力页脚的学习身份表达 |

`apps/api`、`apps/api-go` 和 `homeworks/06-web3-dapp/contracts` 不渲染网页；
`packages/ui` 只提供通用组件且当前没有相关展示词。它们不需要文案改动，但仍由全仓测试和
生产构建覆盖。以后新增前端入口时，也必须遵守本设计的统一表达规则。

## 统一表达规则

线上页面不得用以下词语描述项目身份：

- 作业
- 课程
- 老师
- 验收
- 原始作业能力
- 课程实验

技术语境必须继续准确：BabySteps 仍明确为 Sepolia 测试网产品原型；成长星无价格、不可兑换；钱包、活动和便签内容会公开；GitHub Profile 仍准确描述其数据读取与保存能力。

### 推荐文案映射

| 当前线上表达 | 产品化表达 |
|---|---|
| 课程概念验证 | Sepolia 产品原型 |
| 课程演示 | 测试网体验 |
| 原始作业能力 | 链上家庭便签 |
| 课程实验 | 公开链上功能 |
| 这份作业展示了什么？ | 核心技术能力 |
| 课程验收要点 | 链上交互说明 |
| 课程关键证据 | 完整链上交互闭环 |
| GitHub 个人资料作业 | GitHub 个人资料 |
| AI 全栈课程作业 | AI 全栈个人资料 |
| 课程后续将接入 | 后续版本将接入 |

文案替换以句子自然、信息准确为最终标准，不要求机械逐词替换。

## 页面改造

### BabySteps

- Hero 改为“Sepolia 产品原型 · 测试网”，风险提示改为“仅用于 Sepolia 测试网体验”。
- 钱包引导使用“本产品”“本次测试网体验”等中性表达。
- 链上便签区改为“步骤 4 · 链上家庭便签”和“公开链上便签”。
- 页脚改为“核心技术能力”和“链上交互说明”，继续展示 React、wagmi、Hardhat、receipt 刷新和双账本等工程能力。
- 不降低儿童隐私、公开链上数据、测试币和不可兑换警示的可见性。

### GitHub Profile 与现有主站页面

- 页面标题改为“GitHub 个人资料”，眉题改为“AI 全栈个人资料”。
- 主站入口文字同步改为“GitHub 个人资料”。
- Moments 页面将“课程后续”改为“后续版本”。
- 其他不包含学习身份词的产品页面不做无关改写。

## 路由兼容

公开主路径从 `/homework/github-profile` 调整为 `/projects/github-profile`。

- 所有站内入口统一指向新路径。
- 旧路径保留重定向到新路径，避免历史书签和已分享链接失效。
- 重定向不复制业务页面，GitHub Profile 仍只有一个实际渲染入口。

## 测试策略

- 先增加失败测试，断言公开组件渲染文本不包含禁用的学习身份词。
- 更新 GitHub Profile 页面和主站入口测试，断言标题与链接使用产品化表达。
- 增加路由兼容测试，断言旧路径重定向且新路径渲染原业务页面。
- 保留现有交互测试，确保文案调整不改变钱包、交易、API 或数据库行为。
- 运行主站与 Web3 的 check、test、typecheck 和 build 门禁。

## 完成标准

1. 线上构建中可见元素不再以“作业、课程、老师、验收”等词描述项目身份。
2. GitHub Profile 的站内链接统一使用 `/projects/github-profile`，旧地址仍可访问并重定向。
3. 内部学习文档和证据记录未被产品化改写。
4. BabySteps 的 Sepolia、公开数据、隐私和非金融属性说明保持完整。
5. 主站与 Web3 自动化门禁全部通过。
