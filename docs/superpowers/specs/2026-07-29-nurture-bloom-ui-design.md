# Nurture & Bloom UI 项目基底设计

## 目标

以 Stitch 视觉稿为基底，构建一个可交互、可扩展的 Nurture & Bloom（育爱成长）前端 Demo。第一阶段聚焦 UI 和本地假数据；后续按产品里程碑补充认证、API、数据库和持久化能力，不重写已经完成的页面组件。

## 范围

### 第一阶段包含

- 使用 Better-T-Stack 初始化可运行的 TypeScript Web 应用。
- 使用 React、TanStack Router/Start、Tailwind CSS 构建页面。
- 实现四个核心导航入口：成长、时光、百科、我的。
- 以成长首页作为第一条完整验收链路，呈现宝宝资料、生长指标、里程碑、下一步事项和今日记录。
- 用本地类型化假数据驱动页面，导航、筛选、按钮和基础弹窗具备可见交互反馈。
- 将 Stitch 中的图片复制到项目本地资源目录，不依赖临时外链。
- 建立全局设计令牌：颜色、字体、字号、行高、圆角、间距、阴影、动效和安全区。
- 将重复 UI 拆成可复用组件，并保证移动端优先和桌面端自适应。

### 第一阶段不包含

- 真实登录、注册、权限和会话管理。
- 真实数据库、远程 API、文件上传和云端部署。
- 医疗建议、成长指标诊断或任何需要专业资质的结论。
- GitHub 推送、生产部署和超出当前 UI 项目范围的业务模块。

## 技术方案

采用 Better-T-Stack 的前端优先配置：React + TanStack Router/Start + Tailwind CSS + TypeScript。数据层先通过 `src/data/demo.ts` 提供类型化本地数据，未来把相同的数据访问边界替换为 API/Drizzle 查询；组件不直接依赖数据库。

页面壳层负责全局导航和响应式布局；页面组件负责组合领域组件；领域组件只接收明确的 props；设计令牌集中在全局样式和 Tailwind 主题配置中。后续接入后端时，路由和组件结构保持不变，只替换数据源与表单提交逻辑。

## 页面与交互

### 应用壳层

- 顶部固定导航：品牌标识、通知入口、个人头像。
- 底部固定导航：成长、时光、百科、我的，并显示当前入口。
- 页面内容保留顶部和底部安全区，避免移动端被固定导航遮挡。

### 成长首页

- 宝宝资料卡：问候语、宝宝姓名、年龄和头像。
- 生长曲线卡片：身高、体重、状态标签和轻量装饰曲线。
- 里程碑横向滚动区：已完成里程碑和解锁新技能入口。
- 下一步事项卡：疫苗等提醒信息。
- 今日记录列表：喝奶、睡眠等记录。
- 悬浮添加入口：打开基础记录类型选择/提示弹窗。

### 其他入口

- 时光：展示空状态或本地示例时间线，保留未来接入照片和记录的扩展位。
- 百科：展示分类卡片和搜索/筛选交互的 UI，占位数据由本地文件提供。
- 我的：展示宝宝档案、偏好设置和关于信息的可交互列表。

## 组件边界

- `AppShell`：固定导航、页面容器和安全区。
- `TopBar`：品牌和全局动作。
- `BottomNav`：路由入口与激活状态。
- `BabyProfileCard`：宝宝身份信息展示。
- `MetricCard`：身高、体重等指标卡片。
- `MilestoneCard`：里程碑状态和解锁入口。
- `NextActionCard`：提醒事项展示。
- `RecordItem`：今日记录条目。
- `SectionHeader`：统一标题与辅助操作。
- `FloatingActionButton`：新增入口。
- `Modal`/`Sheet`：基础交互反馈，不绑定业务数据源。

组件通过 props 接收内容和状态，禁止在通用组件内部写死页面文案或模拟数据。

## 视觉系统

沿用 Stitch `DESIGN.md`：暖奶油背景、珊瑚橙主色、婴儿蓝辅助色、薄荷绿状态色、柔粉点缀色；正文和拉丁字符使用 Quicksand 与系统中文圆体回退。8px 间距基线、16px/24px/32px 圆角层级、低透明度环境阴影和半透明模糊导航共同形成 Soft-Tactile Minimalism。所有 token 通过 CSS 变量/Tailwind 主题暴露，组件只使用语义化类名。

## 数据与错误处理

- 本地数据结构使用 TypeScript 类型定义，页面只消费安全的演示数据。
- 空列表、未知记录类型和缺失图片都有明确的空状态或回退展示。
- 交互失败时使用页面内 toast/提示，不使用阻塞式浏览器 alert。
- 不将真实个人、儿童或医疗数据放入演示数据和仓库。

## 验收标准

- 在项目根目录可以启动开发服务器并打开首页。
- 四个底部导航入口可以切换，当前状态正确显示。
- 成长首页主要模块与 Stitch 视觉稿一致：布局、色彩、圆角、字体层级、阴影和间距统一。
- 页面在手机宽度和桌面宽度下均可用，不出现横向溢出或固定导航遮挡内容。
- 新增入口、里程碑入口、查看全部和基本筛选具有可见交互反馈。
- 组件、数据和全局样式边界清晰，后续替换为 API 数据不需要重写页面结构。
- lint、类型检查和生产构建通过。

## 后续演进

完成第一阶段并通过验收后，按课程进度依次补充：Better Auth 登录与宝宝档案、API 路由、Drizzle 数据模型与迁移、记录增删改查、图片存储、测试和部署。每一阶段保持现有组件 API 稳定，并单独定义 Contract 和验收标准。
