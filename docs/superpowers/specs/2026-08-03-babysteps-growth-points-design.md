# BabySteps · 成长星球产品需求文档（PRD）

**日期：** 2026-08-03

**版本：** v1.0

**状态：** 等待用户审阅；功能实现保持暂停

**目标网络：** Ethereum Sepolia 测试网

**目标市场与时区：** 中国优先，北京时间（UTC+8）

## 1. 产品摘要

BabySteps · 成长星球是一款面向成年照护者的 Web3 课程概念验证产品。宝爸宝妈、爷爷奶奶通过专用 Sepolia 测试钱包记录“一起用餐、户外陪伴、亲子共读”等日常陪伴活动，获得不可交易的链上“成长星”，推动原创虚拟伙伴“星宝”改变形态。

本产品借鉴蚂蚁森林、蚂蚁庄园的“完成行为—获得反馈—虚拟伙伴成长”循环，但不复制其形象、文案或商业机制。

本次验证的核心是：

1. 用户主动提交的活动枚举和积分可以写入 Sepolia。
2. 页面刷新后，积分、今日状态和虚拟伙伴阶段仍可从链上恢复。
3. 原始“链上记事本”课程要求可以在同一 DApp 内独立验收。

BabySteps 不能证明现实活动确实发生，不是儿童档案、健康服务、代币项目或 NFT 项目。

## 2. 背景与问题

家庭陪伴通常由许多细小、重复的日常行为组成，完成后缺少轻量、积极且可积累的反馈。BabySteps 用一个通用虚拟伙伴把陪伴行为可视化，让成年照护者看到“今天做过什么”和“虚拟伙伴如何成长”。

区块链只适合承担最小、公开、可验证的状态：测试钱包选择的活动、日期标记和累计积分。儿童姓名、照片、健康、学校和位置等信息不适合进入公开且难以真正删除的公链。

## 3. 目标与非目标

### 3.1 产品目标

- 在一次课堂演示中完成三个活动打卡并看到星宝连续成长。
- 使用北京时间自然日限制同钱包、同活动每日重复领取。
- 让非技术用户理解钱包确认、链上确认和刷新恢复三个关键 Web3 状态。
- 用数据最小化保护儿童隐私：成长主流程不含自由文本或儿童资料。

### 3.2 课程目标

- 使用独立的 Vite + React + TypeScript 前端。
- 使用 wagmi 连接 MetaMask 并调用合约。
- 使用 Hardhat 开发、编译、测试和部署 Solidity 合约。
- 使用水龙头测试币部署到 Sepolia。
- 在 Sepolia Etherscan 完成源码开源验证。
- 完成链上记事本读取、保存、覆盖、清空、交易确认和刷新恢复。
- 留下可追溯的仓库提交、合约地址、交易和 Verified Contract 证据。

### 3.3 本次明确不做

- ERC-20、ERC-721、ERC-1155、转账、提现、价格、交易或兑换。
- NFT 铸造、IPFS、真实孩子照片生成或数字分身。
- 儿童姓名、昵称、生日、年龄、声音、学校、联系方式、位置、路线、疫苗、病历或诊断。
- 相机、相册、麦克风、定位和医疗系统接入。
- 品牌购买凭证、优惠券、随机空投、盲盒、商城或广告画像。
- 家庭多成员授权、共享钱包、社交登录或账户抽象。
- 真实活动认证、预言机、设备数据或防多钱包作弊。
- 连续打卡惩罚、积分倒扣、排行榜和家庭比较。
- 主网部署、生产发布或真实经济价值。

## 4. 用户与使用场景

### 4.1 核心用户

| 用户 | 主要需要 | PoC 中的限制 |
|---|---|---|
| 宝爸宝妈 | 用轻量方式记录日常陪伴并获得积极反馈 | 使用专用测试钱包，不录入儿童资料 |
| 爷爷奶奶 | 大字、少步骤、明确结果 | MetaMask 仍由课程演示者协助操作 |
| 课程老师 | 独立验收记事本、wagmi、Hardhat 和 Sepolia 闭环 | BabySteps 不能掩盖基础作业 |

### 4.2 核心任务

> 当我完成一次日常陪伴时，我希望用一个简单按钮记录活动，并看到星宝发生变化，从而获得温和、可积累的正向反馈。

### 4.3 账户语义

一个 Sepolia 测试钱包对应一份独立的演示进度，不等同于真实家庭身份。家人不得共享助记词或私钥。多照护者协作留待未来用多地址授权实现。

## 5. 产品原则

1. **先满足作业，再做产品加分。** 基础记事本与 BabySteps 分开验收。
2. **不采集优于免责声明。** 成长活动接口不接受文字、照片或位置。
3. **奖励陪伴，不评价孩子。** 不使用“乖、达标、落后、发育等级”等文案。
4. **链上成功以 receipt 为准。** 获得交易哈希不等于已经获得积分。
5. **状态来源必须诚实。** 读取失败不能伪装成 0 分、空便签或未完成。
6. **测试积分不是资产。** 统一称“成长星”，不称代币、收益、挖矿或空投。
7. **虚拟伙伴不是孩子分身。** 只使用原创、通用、预制的卡通形象。

## 6. 范围与优先级

### P0：课程基础层

- 钱包连接与 Sepolia 网络门禁。
- 公开链上便签的读取、保存/覆盖、清空当前值。
- 等待钱包签名、等待链上确认、成功/失败状态。
- 刷新后从链上恢复便签。
- 每笔成功交易提供 Sepolia Etherscan 链接。
- Hardhat 测试、部署和 Etherscan 源码验证。

### P1：BabySteps 增强层

- 三种活动、固定成长星和北京时间每日限制。
- 链上累计成长星与今日完成状态。
- 四种虚拟伙伴视觉状态。
- 刷新后从链上恢复积分、活动状态和形象阶段。
- 活动流程与公开便签完全解耦。

### P2：未来路线图

- 多地址家庭授权、社交登录或账户抽象。
- 可选的链下加密家庭相册或成长档案。
- 可验证品牌凭证、设备签名或预言机。
- 用户主动选择的数字纪念品铸造。
- 长期等级、更多通用场景和非随机装扮。

## 7. 核心用户旅程

### 7.1 BabySteps 主旅程

```text
进入页面
  → 看到 Sepolia 和隐私说明
  → 连接专用测试钱包
  → 切换到 Sepolia
  → 读取成长星、今日活动和星宝阶段
  → 选择一张活动卡
  → 点击“记录这次陪伴”
  → 在 MetaMask 确认
  → 等待 Sepolia receipt
  → 刷新积分、今日状态和星宝阶段
  → 查看链上交易
```

同一活动当天再次访问时，卡片显示“今天已记录，北京时间明天 00:00 后可再次记录”。

### 7.2 公开链上便签课程旅程

```text
进入“公开链上便签（课程实验）”
  → 阅读公开且无法真正删除的提示
  → 输入无个人信息的测试文字
  → 保存并等待 receipt
  → 刷新验证恢复
  → 覆盖当前便签
  → 清空当前便签显示
```

“清空”只更新当前合约状态；历史交易输入仍可能长期公开，界面不得声称“永久删除”。

## 8. 活动、积分与北京时间规则

### 8.1 活动与奖励

| UI 顺序 | 合约枚举 | 成长星 | 用户文案 |
|---:|---|---:|---|
| 1 | `Meal` | +3 | 一起用餐：记录一次轻松的用餐陪伴 |
| 2 | `Walk` | +5 | 户外陪伴：记录一次散步或户外陪伴 |
| 3 | `Read` | +7 | 亲子共读：记录一次故事或阅读时间 |

三项同日全部完成时恰好获得 15 枚成长星，可以在一次演示中走完首轮养成。

### 8.2 每日规则

- 每个测试钱包对每种活动在同一个北京时间自然日只能获得一次成长星。
- 同一个北京时间自然日可以分别完成三种不同活动。
- 北京时间日序号定义为：

\[
\mathrm{dayId}=\left\lfloor\frac{\mathrm{block.timestamp}+8\ \mathrm{hours}}{1\ \mathrm{day}}\right\rfloor
\]

- 页面统一显示“北京时间每天 00:00 更新”。
- 每日限制只能减少同钱包重复提交，不能证明活动真实发生，也不能阻止多钱包操作。

## 9. 虚拟伙伴设计

“星宝”是原创、通用的虚拟成长伙伴。形象不根据真实孩子生成，也不代表孩子的发育、能力或表现等级。

| 链上成长星 | 阶段 | 前端表现 |
|---:|---|---|
| 0–2 | `Egg` | 星星蛋，等待开始 |
| 3–7 | `Sprout` | 冒芽星宝 |
| 8–14 | `Explorer` | 探索星宝 |
| ≥15 | `Star` | 闪耀星宝，解锁故事帽和阅读角场景 |

阶段由累计积分即时计算，不单独保存，避免积分与形象阶段不一致。预制图片和装饰由前端根据阶段选择，不上链、不写入 localStorage，也不铸造成 NFT。

累计成长星不会在跨日时清零。页面始终显示真实总数；首轮进度按 `min(totalPoints, 15) / 15` 计算，最多为 100%。达到 15 后文案改为“首轮养成已完成”，后续积分仍可累计，但本次 PoC 不承诺第二轮形态或奖励。

首次演示按 `Meal → Walk → Read` 操作，积分和视觉依次为：

```text
0 Egg → 3 Sprout → 8 Explorer → 15 Star
```

动画只作为反馈，必须尊重减少动态效果设置，不能成为理解状态的唯一方式。

## 10. 功能需求

### 10.1 钱包与网络

- **FR-W01** 未安装 MetaMask 时显示安装引导，不显示不可用的提交按钮。
- **FR-W02** 未连接时只读取公共说明，不读取为某钱包定制的状态。
- **FR-W03** 钱包连接后显示缩略地址和完整地址复制入口。
- **FR-W04** 非 Sepolia 网络显示明确切换按钮，禁止写入错误网络。
- **FR-W05** 不要求或保存助记词、私钥；只使用浏览器钱包签名。

### 10.2 成长活动

- **FR-G01** 页面显示三张活动卡、固定成长星和今日状态。
- **FR-G02** `recordActivity` 只接收活动枚举，不接收自由文本。
- **FR-G03** 前端提交前模拟调用，合约再次校验每日限制。
- **FR-G04** 用户拒绝签名时保持原状态，并给出可理解提示。
- **FR-G05** 等待签名或确认期间禁止重复提交。
- **FR-G06** receipt 成功后才显示“获得 +N 成长星”。
- **FR-G07** 成功后精确刷新积分、阶段和三项今日状态。
- **FR-G08** 重复活动显示“今天已经记录”，不暴露底层 RPC 错误。
- **FR-G09** 活动提交不能读取、修改、覆盖或清空便签。

### 10.3 虚拟伙伴

- **FR-A01** 未连接时可以显示 0 分的星星蛋预览，但不能冒充链上账户状态。
- **FR-A02** 连接后展示链上累计成长星；15 分前显示 `当前 / 15`，达到后显示“首轮养成已完成”且进度保持 100%。
- **FR-A03** 阶段改变时同时使用图片、文字和进度反馈，不只依赖颜色或动画。
- **FR-A04** 页面刷新后必须从链上积分重新派生阶段。

### 10.4 公开链上便签

- **FR-N01** `getNote`、`setNote`、`clearNote` 作为独立课程功能保持可见可用。
- **FR-N02** 输入上限为 280 UTF-8 字节，前端和合约双重校验。
- **FR-N03** 写入前显示最终内容和“公开、历史不可真正删除”提醒。
- **FR-N04** 保存、覆盖和清空都必须等待 receipt 后刷新读取。
- **FR-N05** 清空按钮文案为“清空当前便签”，并提示历史交易仍公开。
- **FR-N06** `setNote` 和 `clearNote` 不得改变积分、每日标记或星宝阶段。

### 10.5 交易证据

- **FR-T01** 明确区分“请在钱包确认”和“等待测试链确认”。
- **FR-T02** 交易广播后显示缩略哈希；receipt 成功后显示“查看链上交易”。
- **FR-T03** 链接必须指向当前交易的 Sepolia Etherscan 页面。
- **FR-T04** 不使用“活动证明、成长凭证”等可能暗示真实性的名称。

## 11. 信息架构与界面要求

移动端优先的单页顺序：

1. 品牌区：BabySteps、Sepolia 测试网标签和一句话价值。
2. 公开性提示：公链像公开且不能撕掉的公告栏。
3. 钱包卡：安装、连接、地址、网络和切换动作。
4. 星宝主视觉：阶段、成长星和 `当前 / 15` 进度。
5. 三张活动卡：图标、名称、积分、今日状态和主操作。
6. 交易状态：签名、确认、成功、失败和 Etherscan 链接。
7. 公开链上便签：独立且清晰可见的课程实验卡片。
8. 规则与课程说明：数据、限制、作业技术栈和测试网说明。

视觉方向为“温暖成长学习册”：奶油纸张背景、墨蓝正文、嫩芽绿和暖橙点缀。不得直接复制蚂蚁森林或蚂蚁庄园素材。

适老性要求：

- 正文字号不低于 18px，辅助说明不低于 16px。
- 主要点击区域至少 48 × 48px。
- 不依赖悬浮、手势、隐藏菜单或仅颜色传达状态。
- 技术错误必须转译为下一步动作。
- 将 gas 解释为“无价值测试币支付的测试网手续费”。

## 12. 信任、隐私与数据清单

### 12.1 链上数据

- Sepolia 测试钱包地址。
- 活动枚举。
- 北京时间日序号。
- 本次奖励、累计成长星和派生阶段事件。
- 公开链上便签当前值。
- 区块链天然暴露的交易哈希、时间、发送方和调用数据。

钱包地址是化名标识，不应宣传为匿名。

### 12.2 前端静态数据

- 原创星宝图片和预制装饰。
- 活动文案、积分规则和隐私说明。

形象阶段直接从链上积分派生，本次不需要账户数据库或浏览器持久化。

### 12.3 永不收集

- 儿童身份、照片、音视频、生物特征。
- 出生信息、学校、联系方式。
- 精确位置、路线和设备数据。
- 疫苗、病历、诊断和其他健康数据。
- 主钱包私钥、助记词或设备密码。

### 12.4 固定提示文案

顶部提示：

> 课程概念验证 · Sepolia 测试网。成长星无价格，不可转让或兑换。

公开性提示：

> 公链像公开且不能撕掉的公告栏：测试钱包地址、活动类别、交易时间和积分变化可被任何人长期查看。请只使用专用测试钱包。

隐私提示：

> 请勿填写或上传儿童姓名、照片、生日、学校、位置、健康或疫苗信息。

真实性提示：

> 这是成年照护者自报的陪伴记录，不是活动真实性、亲子关系、育儿质量或医疗情况的证明。

虚拟伙伴提示：

> 星宝是通用卡通伙伴，不代表孩子本人，不是 NFT，也没有交易价值。

本节为产品设计边界，不构成法律意见。设计参考《个人信息保护法》中数据最小化、敏感个人信息和不满十四周岁未成年人信息相关要求：<https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm>。

## 13. 技术方案

### 13.1 方案比较

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 扩展现有 `OnchainNotebook` | 一个地址、一次部署和验证，课程证据最清楚 | 同一合约含两个领域 | **采用** |
| 拆成两个合约 | 边界最纯粹 | 两次部署、验证和地址同步，演示复杂 | 不采用 |
| ERC-20 / ERC-721 | 更像完整 Web3 资产 | 引入金融、权限、元数据和安全问题 | 不采用 |

采用“一个合约、两套互不耦合的功能”。前端使用两个独立 hook：

- `useNotebook`：公开便签读取、保存、覆盖、清空。
- `useGrowth`：积分、阶段、今日状态和活动提交。

### 13.2 合约接口

保留课程基础接口：

```solidity
function getNote(address author) external view returns (string memory);
function setNote(string calldata note) external;
function clearNote() external;
```

新增成长接口：

```solidity
enum ActivityType { Meal, Walk, Read }
enum GrowthStage { Egg, Sprout, Explorer, Star }

error ActivityAlreadyRecordedToday(
    address account,
    ActivityType activity,
    uint256 utc8DayId
);

event ActivityRecorded(
    address indexed account,
    ActivityType indexed activity,
    uint256 indexed utc8DayId,
    uint256 reward,
    uint256 totalPoints,
    GrowthStage stage
);

function recordActivity(ActivityType activity) external;
function getGrowthPoints(address account) external view returns (uint256);
function hasRecordedToday(address account, ActivityType activity)
    external view returns (bool);
function getGrowthStage(address account) external view returns (GrowthStage);
function currentUtc8DayId() external view returns (uint256);
```

内部只增加：

```solidity
mapping(address => uint256) private growthPoints;
mapping(address => mapping(ActivityType => uint256))
    private lastRecordedDayMarker;
```

`lastRecordedDayMarker` 保存 `dayId + 1`，避免映射默认值 0 与有效日期混淆。奖励和阶段阈值固定在合约逻辑中，不提供 owner 调整、管理员重置、补分或扣分入口。

活动枚举序号是 ABI 的一部分，部署后不能调换：`0=Meal`、`1=Walk`、`2=Read`。

### 13.3 交易状态机

```text
idle
  → awaiting_signature
  → submitted(hash)
  → confirming
  → confirmed(receipt)
  → refetching
  → success
```

任何阶段失败都进入可恢复错误态。用户拒签保留页面状态；链上回滚映射为明确业务提示；RPC 读取失败提供重试，不能显示伪造默认值。

## 14. 错误处理

| 场景 | 用户提示 | 恢复动作 |
|---|---|---|
| 未安装 MetaMask | 未检测到钱包 | 显示官方安装入口 |
| 未连接 | 请先连接家庭测试账户 | 连接钱包 |
| 网络错误 | 当前不是 Sepolia 测试网 | 一键请求切换 |
| 用户拒签 | 已取消，本次没有写入测试链 | 可再次提交 |
| 今日重复 | 今天已经记录，明天北京时间 00:00 后再来 | 禁用该活动卡 |
| 交易回滚 | 本次交易未成功，成长星没有变化 | 保留原链上状态 |
| RPC 读取失败 | 暂时无法读取链上状态 | 显示重试，不显示 0 分 |
| 便签超长 | 内容超过 280 UTF-8 字节 | 显示当前字节数 |
| 合约地址无效 | 当前版本尚未正确配置 Sepolia 合约 | 禁止构建/写入 |

若活动已在当天完成，现场重演使用另一个专用 Sepolia 测试账户或预先录制的证据；不得加入管理员重置后门。

## 18. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用户误填儿童信息 | 公链难以真正删除 | 活动流取消文本；便签独立且强提示，只用测试句 |
| “链上证明活动”误解 | 夸大产品可信度 | 统一写“照护者自报”，链接叫“查看链上交易” |
| 成长星被理解为代币 | 金融和价值误导 | 不实现 Token 标准；统一写不可交易的测试积分 |
| 一个钱包被当成家庭账户 | 诱发共享私钥 | 定义为一份演示进度，明确禁止共享助记词 |
| BabySteps 掩盖作业 | 老师无法验收基础功能 | P0/P1 分层、独立 UI、独立 hook 和独立测试 |
| 当日状态导致无法重演 | 现场演示中断 | 使用备用专用测试账户或预录证据，不设 reset |
| 前端把 hash 当成功 | 展示不存在的积分 | receipt 成功后再刷新与显示奖励 |
| ABI、地址和部署漂移 | 操作错误合约 | 生产地址强校验；QA 关联提交、地址和 Verified 源码 |

## 20. 已确认决策

1. 产品名为 `BabySteps · 成长星球`，虚拟伙伴名为“星宝”。
2. 中国优先，按北京时间 UTC+8 每日 00:00 更新。
3. 活动为一起用餐、户外陪伴、亲子共读；成长星为 3、5、7。
4. 每个测试钱包对每种活动每日一次，三项同日可分别完成。
5. 15 枚成长星完成首轮养成。
6. 星宝为原创通用虚拟伙伴，不使用孩子照片，不是 NFT。
7. 成长活动不包含自由文本；公开便签是独立课程实验。
8. 成长星记录在 Sepolia，不是 ERC-20，不可转让、交易、提现或兑换。
9. 一个测试钱包只代表一份独立演示进度，不要求家庭共享钱包。
10. 本次不部署主网，不发布生产产品。

## 21. 同学作业的取长补短

本设计参考用户提供的公开作业，但不复制源码：

- 采用钱包签名与 receipt 确认分阶段、确认后刷新、错误网络门禁和 Etherscan 链接。
- 采用 hook 管理读取/写入边界、ABI/地址同步思想和明确的加载/空态/错误态。
- 保留 UTF-8 字节计数、删除确认和部署—源码—页面可追溯性。
- 不采用多笔记线性扫描、静默地址回退、零 WalletConnect 配置、仅前端限制或仓库与生产页不对应的证据。

## 22. 评审结论

课程、亲子产品、Web3 和隐私四个视角的交叉评审形成以下共识：

- P0 记事本和 P1 BabySteps 必须独立验收。
- UTC 规则统一改为北京时间 UTC+8。
- “单张徽章”升级为积分派生的四状态虚拟伙伴。
- `recordActivity` 和事件彻底移除自由文本。
- “健康里程碑”替换为“亲子共读”。
- 隐私依靠不采集，而不是只依靠提示语。
- 公链只能证明测试钱包提交了交易，不能证明活动、亲子关系或育儿质量。

本 PRD 已无待定功能项。任何新增范围必须先判断是否影响 P0 课程门槛、儿童隐私或 Sepolia 可演示性。
