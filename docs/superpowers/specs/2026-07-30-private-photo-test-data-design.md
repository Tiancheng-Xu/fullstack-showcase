# 本地家庭照片测试数据设计

## 目标

将 `/Users/shier/Desktop/🍊` 中的真实家庭照片整理为 `course-homework` 的本地测试数据。系统自动补齐拍摄日期、标题、描述、封面和照片分组，使“家庭时光”页面可以用接近真实的数据进行本机测试。

照片涉及未成年人，整个流程默认本地运行。原图、派生图和生成的数据不得提交 GitHub，也不得上传 Cloudflare 预览环境。

## 数据范围

收录以下目录中的真实照片：

- `/Users/shier/Desktop/🍊/23天上门照`
- `/Users/shier/Desktop/🍊/自己拍的`

排除以下内容：

- `AI生成`
- `BaoBao_Puff_动图`
- `hatch-pet-baobao-puff`
- `雕刻图案`
- 信息图及其他非相机照片

扫描器使用明确的目录允许列表，而不是仅凭扩展名判断。当前预计处理 78 张真实照片。

## 日期规则

日期必须代表拍摄时间，按以下优先级解析：

1. 图片 EXIF `DateTimeOriginal`。
2. 其他可信的相机创建时间字段。
3. 文件名中的时间，例如 `IMG_20260723_111516`。
4. 微信文件名中的导出时间只作为低可信度候选，并在数据中标记来源。

文件系统创建时间和修改时间不得冒充拍摄时间。无法可靠确定时间的照片进入待确认列表，不自动写入虚假日期。

每条记录同时保留：

- ISO 8601 格式的机器可读时间。
- 面向页面显示的中文日期。
- 日期来源和可信度。

## 相似照片分组

不同场景分别形成家庭时光记录。连拍、相同姿势、原图与精修副本等高度相似照片合并到同一组。

分组依据：

- 拍摄时间接近程度。
- 图片感知哈希相似度。
- 尺寸、文件名和父目录关系。
- 精修子目录与原始拍摄目录的对应关系。

分组只建立关联，不移动、覆盖或删除原图。每组保留全部成员照片。

## 封面选择

系统为每组自动选择一张封面，综合考虑：

- 清晰度。
- 分辨率。
- 曝光是否明显异常。
- 是否为精修版本。
- 与组内其他图片相比的信息完整度。

封面选择结果可以人工修改。自动流程不得删除未被选中的照片。

## 标题与描述

每个照片组生成一个简短标题和一段温暖的家庭纪念描述。

描述只能使用图片和目录中能够确认的信息：

- 可以描述姿势、表情、服装、背景色调和画面氛围。
- 可以使用目录中明确给出的阶段信息，例如“第 23 天”。
- 不识别人脸身份，不推测姓名、精确地点、健康状况或未发生在画面中的事件。
- 不把不确定内容写成事实。

相似照片共享组级标题和描述；每张成员照片保留自己的文件名、拍摄时间和排序。

## 数据结构

生成的本地数据由相册组和成员照片组成：

```ts
type LocalPhoto = {
  id: string;
  sourcePath: string;
  localUrl: string;
  capturedAt: string | null;
  capturedAtSource: "exif" | "camera-metadata" | "filename" | "wechat-filename" | "unknown";
  capturedAtConfidence: "high" | "medium" | "low";
  width: number;
  height: number;
};

type LocalMoment = {
  id: string;
  title: string;
  description: string;
  capturedAt: string | null;
  displayDate: string;
  coverPhotoId: string;
  sourceAlbum: "23天上门照" | "自己拍的";
  photos: LocalPhoto[];
};
```

生产代码只依赖抽象后的 `LocalMoment` 数据，不直接保存桌面绝对路径。

## 本地文件布局

本地测试资产放在 Web 应用内部的忽略目录：

```text
apps/web/apps/web/public/private-test-data/
  photos/
  moments.generated.json
  review-required.json
```

生成过程复制用于测试的工作副本，不修改原始照片。该目录以及任何映射清单必须加入 `.gitignore`。

Git 仓库只提交：

- 数据生成工具。
- 数据类型。
- `.gitignore` 规则。
- 不含真实照片或绝对路径的测试夹具。

## 页面接入

本地开发时，如果 `moments.generated.json` 存在，“家庭时光”页面读取本地照片数据；文件不存在时继续使用仓库中的安全占位数据。

这样可以保证：

- 本机能够测试真实照片的布局、加载和分组。
- GitHub Actions 与 Cloudflare 预览不依赖私人文件。
- 公开预览不会因缺少本地数据而报错。

## 隐私与安全

- 不上传真实照片到外部视觉服务。
- 不把照片、绝对路径、EXIF 定位信息或生成描述发送到代码审查服务。
- 工作副本清除 GPS 等不需要的 EXIF 元数据。
- 生成清单中只保留页面需要的字段。
- 执行 Git 提交前，自动检查私人测试目录未被跟踪。

## 错误处理

- 日期缺失：写入待确认清单，不猜测日期。
- 图片无法读取：跳过该文件并记录本地错误。
- 相似度处于边界：不自动合并，放入待确认清单。
- 描述无法可靠生成：使用基于目录和日期的中性标题，避免虚构内容。
- 本地数据不存在：页面回退到安全占位数据。

## 验收标准

- 只处理允许目录中的真实照片。
- 优先采用真实拍摄时间，并记录日期来源和可信度。
- 高度相似的照片被分组，所有原图仍完整保留。
- 每组有可解释的封面选择结果。
- 标题和描述温暖但不虚构敏感事实。
- 本机“家庭时光”页面能够显示生成数据。
- Git 状态、Git 历史和 Cloudflare 预览中不包含真实照片、桌面绝对路径或定位元数据。
