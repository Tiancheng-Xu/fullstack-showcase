# 课程知识助理训练数据扩充设计

日期：2026-08-02

## 1. 背景

`RAG 与 Agent 编排` 作业已经准备了第一版 Qwen3-8B QLoRA 数据集 `rag-sft-20260802-v1`。该版本包含 63 条审核通过样本，划分为 50 条训练、7 条验证和 6 条测试，适合验证 CUDA、QLoRA、Adapter 重载和评测闭环。

当前样本中有 55 条使用宽泛的 `learn` 主题，细分知识覆盖、教学对话、困难负例和多轮追问不足。第二版数据集的目标不是延长 GPU 计费时间，而是把模型从“能完成冒烟训练”推进为可用的课程知识助理。

## 2. 目标与非目标

### 2.1 目标

1. 发布正式第一版训练数据：`train` 至少 300 条，独立 `validation` 与冻结 `test` 不计入 300；质量允许时推荐约 1000 条。
2. 训练模型用大白话解释课程概念，并能使用类比、对比、步骤和小测验帮助学习。
3. 覆盖 RAG、向量数据库、Rerank、Mastra、LangChain、LangGraph、Qwen3、QLoRA 和 CUDA 训练等本次作业核心知识。
4. 增加多轮澄清、故障诊断、错误纠正、权限和隐私边界样本。
5. 保留第一版不可变数据与 Adapter，使第二版既可从基座重训，也可作为后续增量训练来源。

### 2.2 非目标

- 不复制或上传完整学习笔记、课程逐字稿或其他私有原文。
- 不通过低质量同义改写把数据机械扩充到数百条。
- 不要求模型仅凭微调记住全部课程事实；需要实时性或精确出处的内容仍由 RAG 提供。
- 不在 Mac 上执行训练，也不在本阶段启动 UU 云真机。

## 3. 助理行为

课程知识助理按以下顺序回答：

1. 优先使用课程资料中稳定、已核验的知识与表达方式。
2. 课程资料不足时，允许使用模型的通用知识直接补充。
3. 按用户要求，通用知识补充不增加“非课程内容”等显式标识。
4. 当问题要求精确版本、实时事实、原文引用或无法可靠判断时，不编造答案，应建议检索或核验。
5. 涉及凭据、个人信息、付费启动、生产写入和不可逆操作时，先说明风险并遵守确认边界。

第 3 条取代原设计中“所有课程来源与外部知识都必须在回答中显式区分”的训练行为。该取舍提升回答流畅性，但会降低用户对知识来源的可见性；RAG 界面仍应在检索到课程证据时展示正常引用。

## 4. 数据组成

第二版正式 `train` 按以下目标比例平衡，允许根据课程目录的实际覆盖上下浮动 5 个百分点：

| 能力 | 目标比例 | 典型任务 |
| --- | ---: | --- |
| 课程概念与教学解释 | 40% | 大白话解释、类比、概念关系、学习顺序、小测验 |
| RAG、向量库与 Rerank | 20% | 切片选择、混合召回、重排、引用、冲突与检索失败 |
| Mastra、LangChain 与 LangGraph | 15% | 框架对比、状态编排、工具调用、失败恢复和评测 |
| Qwen3、QLoRA 与 CUDA | 10% | 数据准备、显存处理、训练证据、Adapter 重载和增量训练 |
| 故障诊断与错误纠正 | 10% | 先定位边界、验证假设、纠正常见误解、避免错误传播 |
| 隐私、权限与危险操作 | 5% | 数据外发、凭据、付费资源、生产写入和确认策略 |

新增样本不只采用单轮问答。目标是约 65% 单轮教学、20% 多轮追问、15% 反例或边界任务。回答长度保持适合 Qwen3-8B QLoRA：优先短而完整，复杂架构题才使用分层长答案。1K–10K 的后续扩充只补真实主题、平台和失败边界，不做同义改写凑数。

## 5. 来源与生成规则

1. 只读取学习笔记的必要章节和结构，提取稳定概念、关系与实践目标。
2. 所有问答使用原创表述，不复制长段课程原文，也不保留真实姓名、联系方式、凭据、账户和本机路径。
3. 每条样本记录来源标识、主题、能力类型和审核状态，但训练回答不暴露本机来源路径。
4. 同一概念只在学习目标明显不同时生成多个样本，例如“解释”“比较”“排错”和“实践设计”，不得只做同义改写。
5. 生成草稿后必须经过去重、隐私扫描、泄漏检查和人工规则审核；未通过的样本进入拒绝清单，不得为了达到数量目标自动放行。

## 6. 版本与增量训练

- `rag-sft-20260802-v1` 保持不可变。
- 新样本形成独立来源批次，并发布新的不可变正式数据版本；建议 release ID 为 `rag-sft-20260802-v2`，实际创建时按项目的不可变命名规则冻结。
- v2 的发布清单记录 v1 的父版本、样本 Hash、来源批次、划分和生成时间。
- 划分以知识主题和来源组为单位，近似问题不得跨越训练、验证和测试集合。
- v1 的 50 条 train 仍只代表 smoke；只有重新审核后满足正式质量要求的样本才可作为 v2 replay，并计入至少 300 条 train。
- 冻结测试集保留 v1 的核心回归题，并新增课程知识助理、面试、架构、执行、`grill-me` 和安全专项题；测试题不得进入训练数据。
- 训练时先完成小规模 smoke run，再比较“基座”“v1 Adapter”和“v2 Adapter”。若从 v1 Adapter 继续训练，必须保留 v1 Adapter，不覆盖原文件。

## 7. 质量门槛

每条样本必须同时满足：

1. 问题自然、目标明确，不依赖缺失上下文。
2. 答案正确、可执行，关键条件和边界没有遗漏。
3. 回答体现教学价值，而非只给术语定义。
4. 不含秘密、个人数据、私有路径或可还原课程原文的长片段。
5. 与现有样本不存在高相似重复。
6. 不把课程中的历史性观点冒充为不可变的当前事实。

数据集发布前必须通过现有 schema、去重、泄漏、隐私、安全、划分和 bundle 验证。任何校验失败都阻止生成上传包。

## 8. 评测设计

冻结评测覆盖以下能力：

- 用初学者能理解的方式解释课程概念；
- 比较相近技术并给出选择条件；
- 面对不完整问题先补齐必要上下文；
- 诊断 RAG 检索、Rerank、Agent 编排和 CUDA 训练故障；
- 课程资料不足时仍能给出正确、自然的通用知识回答；
- 面对无法可靠回答或危险动作时不编造、不越权；
- v2 不应导致 v1 已通过能力明显退化。

评测至少记录格式遵循、概念正确性、教学清晰度、边界遵守和回归保持五项结果。训练 loss 不能单独作为完成证据。

## 9. 远程训练包

远程包只包含：

- v2 的脱敏 `train`、`validation` 和冻结 `test` JSONL；
- 数据与文件 Hash 清单；
- QLoRA 配置、预检、评测和证据收集脚本。

完整学习笔记、草稿、拒绝样本、本机绝对路径、凭据和个人信息不得进入上传包。上传前在本地重新验证允许列表、ZIP 内容和 SHA-256；上传后在远程机器核对同一 Hash。

## 10. 验收标准

1. 正式 `train` 不少于 300 条，独立 `validation` 与冻结 `test` 另计，能力比例符合第 4 节约束；质量允许时推荐约 1000 条。
2. v1 保持不可变，v2 具有父版本、文件清单和 Hash。
3. 新增样本通过 schema、质量、去重、隐私、泄漏和划分检查。
4. 冻结测试集与训练集不存在题目或答案泄漏。
5. 新的隐私安全上传包可重复构建并通过本地验证。
6. UU 云真机仍需在用户进行计费确认后才能启动。
