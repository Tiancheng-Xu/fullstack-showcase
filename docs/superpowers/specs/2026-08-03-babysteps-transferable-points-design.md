# BabySteps Sepolia 可转让成长积分设计

## 目标

在现有 BabySteps 概念验证版中加入 Sepolia 钱包间成长积分转让，同时保留“照护活动
驱动星宝成长”的产品含义。功能必须满足课程演示，不扩展成具有价格、兑换、授权或
交易市场能力的代币系统。

## 已确认方案

采用双账本：

1. **累计成长值**：仅由当前钱包记录 Meal、Walk、Read 活动获得，只增不减，继续
   决定 Egg、Sprout、Explorer、Star 阶段。
2. **可转余额**：记录活动时同步增加，可以直接赠送给另一个 Sepolia 钱包；收到的
   余额可以再次赠送，但不会增加收款钱包的累计成长值或星宝阶段。

因此，转出积分不会让星宝退化，收取积分也不能冒充收款人完成了现实照护活动。

## 明确排除范围

- 不实现 ERC-20、ERC-721 或 ERC-1155。
- 不提供 `approve`、`allowance`、代扣、交易撮合、价格、兑换或提现。
- 不把成长积分描述为资产、投资、收益或真实活动证明。
- 不支持主网部署；课程验收只使用 Sepolia 和专用测试钱包。
- 不在交易中写入儿童姓名、照片、位置、健康、疫苗或其他私人资料。

## 合约设计

### 状态与读取

保留现有 `growthPoints` 作为累计成长值，确保 `getGrowthPoints(address)` 和
`getGrowthStage(address)` 的含义不变。新增：

```solidity
mapping(address account => uint256 balance) private transferableBalances;

function getTransferableBalance(address account) external view returns (uint256);
```

`recordActivity` 在通过北京时间每日限制后，同时把奖励加到 `growthPoints` 和
`transferableBalances`。活动事件继续表达活动带来的累计成长结果，不包含儿童文字。

### 转让接口

新增：

```solidity
function transferGrowthPoints(address recipient, uint256 amount) external;
```

执行顺序：

1. 拒绝零地址、发送给自己和数量为零；
2. 检查发送方可转余额不少于数量；
3. 扣减发送方可转余额并增加接收方可转余额；
4. 发出完整、可索引的公开事件。

```solidity
event GrowthPointsTransferred(
    address indexed sender,
    address indexed recipient,
    uint256 amount,
    uint256 senderBalance,
    uint256 recipientBalance
);
```

采用自定义错误表示无效接收方、自己转账、零数量和余额不足。所有状态修改发生在事件
之前，函数不进行外部合约调用，因此没有回调重入面。Sepolia 转账仍不可逆，用户必须
在 MetaMask 中核对接收地址、网络和数量。

当前尚未部署真实 Sepolia 合约，因此不需要代理升级或旧数据迁移；最终只部署通过
完整测试的新版合约。

## 前端架构

### 数据与交易边界

保持 `useGrowth` 负责活动累计值、阶段和每日状态。新增独立的
`usePointTransfer` hook，负责：

- 读取当前钱包的可转余额；
- 校验接收地址、正整数数量、非本人地址和余额；
- 在请求签名前使用 `simulateContract` 预演；
- 调用钱包签名并等待成功 receipt；
- 成功后刷新发送方余额，并让接收方地址的余额查询失效；
- 区分等待签名、等待链确认、成功、拒签、合约错误和读取错误。

不使用乐观余额：只有成功 receipt 后才更新链上显示。ABI 新增余额 getter、转让函数、
转让事件和自定义错误。

### 页面交互

成长区把原来的“累计成长星”改为两个清晰指标：

- `累计养成值`：决定星宝阶段；
- `可赠送成长星`：当前可转余额。

新增“赠送成长星”卡片，包含接收钱包地址、正整数数量、余额提示和提交按钮。按钮在
钱包未连接、网络不是 Sepolia、输入无效、余额不足或已有交易处理中禁用。提交前固定
显示以下提示：

> 接收地址、数量和交易会长期公开；测试链转账无法撤回，请逐字核对地址。

签名、广播、确认和错误状态使用文字及 `aria-live`/`role="alert"`，成功后提供 Sepolia
Etherscan 交易链接。320px 宽度不出现横向溢出，输入和按钮保持至少 48px 高。

页面价值说明调整为“成长星无价格，只用于 Sepolia 课程演示；可在测试钱包间赠送，
不可兑换”。公开便签仍是独立 P0 课程实验，不与积分转让共用输入或交易状态。

## 错误与安全处理

- 地址必须是有效 EVM 地址；前端检查提升体验，合约检查提供最终安全边界。
- 不允许转给零地址或自己，避免无意义或不可恢复的误操作。
- 数量只接受十进制正整数，不支持小数；1 个单位就是 1 枚成长星。
- 余额不足先在前端禁用，合约仍必须独立拒绝。
- 钱包拒签与链上失败不改变显示余额，并提供可理解的中文错误。
- 任何成功提示必须以成功 receipt 为依据，不能只依赖 transaction hash。
- 前端不读取或保存私钥；地址和数量属于公开链上信息。

## 测试与验收

### 合约测试

- 三类活动同时增加正确的累计成长值和可转余额。
- 成功转让更新双方可转余额并发出完整事件。
- 转出不会降低发送方累计成长值或阶段。
- 收到积分不会增加接收方累计成长值或阶段。
- 零地址、本人、零数量和余额不足均回滚，双方状态不变。
- 转让与每日活动、公开便签状态互不影响。

### 前端测试

- ABI 与合约接口一致。
- hook 在写入前模拟，等待 receipt 后才刷新余额。
- 正确处理地址、数量、本人地址、余额不足、拒签和合约错误。
- 页面同时显示累计养成值与可转余额，不把收到的余额计入阶段。
- 交易处理中阻止重复提交，成功链接指向 Sepolia Etherscan。
- 转让输入不接受儿童资料，只接受公开钱包地址和整数数量。

### 真实 Sepolia 验收

部署前再次运行全部本地检查，并在外部 Chrome 中确认专用 MetaMask 测试账户和
Sepolia 网络。使用两个专用测试地址完成一次赠送，刷新后核对双方余额、发送方阶段
不变、接收方阶段不变以及 Etherscan 事件。任何真实部署、领水或钱包签名都在最终
动作前单独确认。
