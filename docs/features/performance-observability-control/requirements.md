# 性能观测控制与历史快照兜底要求

## 用户目标

在 Dashboard 与 Evidence 同时展示真实性能状态；AWS 观测链停止或故障时，保留并明确展示最近一次可信快照；管理员从统一、受保护的入口启停项目临时观测资源，以控制成本。

## 必须实现

1. Dashboard 与 Evidence 复用同一性能状态卡和控制入口。
2. `controlState` 与 `dataMode` 正交建模，避免把“资源已停止”和“数据不可用”混为一谈。
3. 实时链不可用时，只回退到校验通过的最后成功快照；无快照时展示可信空状态，不造假数据。
4. D1 保存项目状态、操作、generation、幂等键和公开审计投影。
5. R2 保存应用层不可变快照，校验 schema、敏感字段与 SHA-256 后才更新 `latest.json`。
6. 控制面由 Cloudflare Access 保护，Worker 也必须校验 Access JWT；浏览器不接触 AWS 或 GitHub 凭据。
7. Worker 只能触发注册表中固定仓库、固定 workflow 与固定 Environment。
8. 启动前必须验证上次清理完成，项目临时 Stack、Schema、Role 和运行资源为空。
9. 停止流程必须先关采集、处理队列，再生成最终快照、删除项目资源并证明共享资源未变化。
10. Evidence 必须记录本设计、运行架构、启动/停止时序、Actions、预览与灰度、权限、成本、清理和真实验证证据。

## 最低验收线

- Dashboard 与 Evidence 显示一致的状态、数据模式、快照时间和来源。
- 停止/故障时仍显示最后可信快照，并明确标注“历史数据 · 当前非实时”。
- 双击、重试、乱序 webhook 不会重复启动或覆盖新 generation。
- 清理后项目资源为空，共享 VPC、NAT、RDS、ALB、OIDC 与日志基础设施未被删除。
- 无凭据、个人信息、私有运行链接或原始日志进入公开页面。

## 当前版本不做

- Athena、Glue、Firehose：作业规模不足以抵消额外数据管道、权限和维护成本。
- 常驻 ECS：按分钟运行的一次性任务即可完成清洗，常驻服务会持续计费。
- 每项目一套 OAuth/OIDC：复用 Cloudflare Access 与账户级 GitHub OIDC，减少配额、密钥和审计面。
- 通用 AWS 管理控制台：只允许项目级 start/stop，避免把受约束控制面扩成高风险云控制台。
- AI Agent 自动删除或重放资源：Agent 可给建议和只读诊断；删除、重放必须由固定工作流和明确人工动作执行。
