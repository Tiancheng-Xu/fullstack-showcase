# 单层撕纸玻璃项目视觉方向

## 1. 使用目的

这份文件记录 Showcase Dashboard 已确认的视觉优化方向，供后续项目作为设计参考。

它不是要求所有项目复制 Dashboard 的米色、靛蓝或朱红配色。其他项目应保留自己的产品主题、品牌识别和信息架构，只复用以下设计原则：

- 撕纸轮廓与半透明玻璃必须是同一个视觉图层。
- 背景需要透过卡片产生模糊、折射和明暗变化，玻璃效果应当可感知。
- 颜色服务于项目身份和信息状态，不使用无意义的霓虹装饰。
- 重要文字必须保持稳定对比度，视觉效果不能牺牲可读性。
- 图标底板同样使用轻量半透明玻璃，只保留图标自身识别色。

## 2. 核心视觉合同

### 2.1 单层材质

项目卡只有一个主要轮廓：不规则撕纸形状的半透明玻璃。

禁止使用“外层玻璃矩形 + 内层撕纸卡片”的嵌套结构。边框、玻璃表面、纸张纤维和内容必须属于同一张卡片。

推荐组合：

```css
.project-card {
  border: 1px solid transparent;
  clip-path: polygon(/* 项目可调整的不规则撕纸轮廓 */);
  background:
    linear-gradient(145deg, var(--glass-highlight), var(--glass-tint)) padding-box,
    linear-gradient(135deg, var(--edge-start), var(--edge-mid), var(--edge-end)) border-box;
  backdrop-filter: blur(18px) saturate(0.82);
  box-shadow:
    inset 1px 1px rgb(255 255 255 / 78%),
    inset -1px -1px var(--glass-edge-shadow);
  filter: drop-shadow(0 16px 20px var(--card-shadow));
}
```

实现时可以使用 SVG mask、CSS mask 或项目已有的图形方案改善撕裂细节，但不能新增第二层卡片冒充撕纸边界。

### 2.2 玻璃透明度

玻璃不是白色纸片。卡片背后的主题图案应当可以被看见，但必须经过模糊和轻微折射。

建议：

- 背景透过率保持在约 `20%–32%`，再根据文字密度调整。
- `backdrop-filter` 建议从 `blur(14px)` 到 `blur(20px)`。
- 标题和正文附近允许增加局部雾化层，但不应覆盖整张卡片。
- 使用左上内高光和右下密度阴影表现玻璃厚度。
- 禁止把高透明度用于长文本而不提供可读性保护。

### 2.3 边缘颜色

边缘渐变必须结合项目自己的主题色，而不是统一复制紫色。

每个项目定义以下语义 token：

```css
:root {
  --project-ink: /* 主要文字与图标色 */;
  --project-accent: /* 关键操作与状态色 */;
  --glass-tint: /* 玻璃底色 */;
  --edge-start: /* 项目主色的低饱和版本 */;
  --edge-mid: /* 中性色或辅助色 */;
  --edge-end: /* 项目强调色的低饱和版本 */;
}
```

边缘应以折射为主，不以发光为主：

- 大部分轮廓保持细、淡、稳定。
- 只在少量撕裂转折处保留微弱亮点。
- 禁止整圈霓虹、强外发光、高饱和蓝紫渐变。
- 警告、失败、完成等状态色不能被装饰渐变覆盖。

Dashboard 当前采用低饱和靛灰到灰紫的边缘折射，并只把朱红用于印章、编号和关键进度。其他项目应根据自身主题重新映射。

### 2.4 项目图标

图标不使用深色实心方块作为背景。图标底板采用小尺寸磨砂玻璃：

```css
.project-icon {
  color: var(--project-ink);
  border: 1px solid rgb(255 255 255 / 72%);
  background: linear-gradient(145deg, rgb(255 255 255 / 46%), rgb(225 233 234 / 22%));
  backdrop-filter: blur(12px) saturate(0.84);
  box-shadow: inset 0 1px rgb(255 255 255 / 88%);
}
```

- 图标本体保留项目识别色。
- 底板只负责提供对比度，不成为第二个视觉焦点。
- 不应把所有图标强制改成白色或同一种颜色。
- 图标没有品牌资产时，使用语义明确、线宽统一的图形图标。

## 3. 信息层级

卡片内容优先级固定为：

1. 项目状态和项目名称。
2. 一句话价值说明。
3. 进度或交付状态。
4. 简要架构与关键难点。
5. 技术标签。
6. 项目主页与工作证明入口。

装饰图案只能作为背景点缀，不得删除节点说明、架构文字、限制或证据状态。

## 4. 交互状态

- Hover 只允许轻微位移、阴影或边缘清晰度变化，不使用剧烈缩放。
- Focus 必须有稳定、清晰且不依赖颜色渐变的轮廓。
- 触控目标最小 `44px`。
- `prefers-reduced-motion` 下关闭非必要位移动画。
- 不支持 `backdrop-filter` 时，降级为高不透明度主题底色，保证内容仍可读。

## 5. 项目适配流程

其他项目采用该方向时，应按以下顺序实施：

1. 保留项目原有设计 token、字体、状态色和信息结构。
2. 从项目主色中生成低饱和边缘色，不直接复制 Dashboard 配色。
3. 先实现单层撕纸轮廓，再增加玻璃透明度与折射。
4. 调整局部文字雾化，保证正文与标签可读。
5. 将实心图标底板替换为轻量玻璃底板，保留图标识别色。
6. 对首页、项目主页、工作证明和主要深链做一致性检查。
7. 把最终设计选择、差异和限制写入该项目自己的 Evidence。

## 6. 验收 Gate

### 视觉与响应式

- `375 / 390 / 430 / 1440` 使用同一组件树。
- 无根级横向滚动。
- 撕纸边缘和玻璃表面视觉上属于同一图层。
- 背景在卡片内部可见且经过模糊或折射，不能退化成不透明白卡。
- 图标底板半透明，图标识别色清晰。
- 正文对比度至少满足 WCAG AA；装饰色不能代替文字状态。

### 视觉回归

- 重要页面使用 BackstopJS 或仓库既有等价工具。
- 覆盖固定路由、固定数据和 `375 / 390 / 430 / 1440`。
- Candidate 差异必须人工检查，禁止为通过 Gate 盲目更新 baseline。
- 同时检查 HTTP/路由语义、`pageerror` 和根级横向溢出。

### 功能边界

- 视觉调整不得修改项目状态、进度、性能口径或 Evidence 事实。
- 项目主页、工作证明和作品集首页互链保持有效。
- 禁止把 Preview、本地截图或 Mock 数据描述为生产验证。

## 7. 禁止事项

- 不创建“玻璃容器套撕纸卡片”的双层结构。
- 不使用整圈高饱和紫色、蓝色或彩虹霓虹。
- 不让背景图案穿透到影响文字阅读。
- 不用过多圆角、胶囊按钮或悬浮阴影破坏项目自身设计语言。
- 不为了统一外观而覆盖项目品牌色、状态语义或可访问性规则。
- 不把本文件作为强制像素模板；它只定义材质、层级和质量边界。

## 9. 文档维护规则

本文件是该视觉方向的当前权威说明。后续对撕纸轮廓、玻璃透明度、边缘颜色、图标材质、信息层级、响应式行为、可访问性或视觉回归 Gate 的任何有效优化，都必须在同一改动中同步更新本文件。

维护要求：

- 先记录项目实践中发现的问题、适用范围和真实结果，再决定是否泛化。
- 只把跨项目可复用的原则写入本文件；项目专属配色、品牌资产和业务布局保留在各项目内部。
- 变更必须说明新增规则、替代规则和兼容或降级边界。
- 如果实现与本文件冲突，应先修正实现或更新合同并说明原因，禁止长期漂移。
- 其他任务引用本方向时使用本文件，不依赖聊天截图或临时口头约定。

## 10. 全站材质层级

实践确认后，撕纸玻璃方向不只应用于项目卡，而应覆盖同一作品站点的完整体验。不同区域使用同一材质体系，但强度必须分层：

1. 项目卡：使用最明显的单层撕纸轮廓、背景折射和项目图标玻璃底板。
2. 简历、性能、Evidence 和架构内容块：使用平整的半透明纸玻璃，不重复使用强撕裂边缘。
3. 页头、页脚和移动端导航：使用连续磨砂玻璃条，保证滚动和导航稳定。
4. Hero 与说明文字：使用局部雾化玻璃，只保护文字区域，不形成大面积白色遮罩。
5. 当前导航：使用项目强调色细线和低透明度染色，不使用高饱和实心按钮或重阴影。
6. 次级标签与操作入口：保持透明、边界清晰、触控目标不小于 44px。

全站统一的是材质语言和层级关系，而不是把每个区域都做成相同卡片。项目接入时仍须按自身主题重新映射颜色、纹理和装饰图案。

## 11. 内容保留与首屏构图

视觉换肤不得删除原站的简历、性能观测、项目状态、架构、技术标签、链接或 Evidence。Dashboard 首屏可以调整信息顺序，但必须保留全部内容：

- Hero 和项目列表优先出现在首屏，形成作品入口。
- 简历与性能模块下移继续完整展示，不因视觉参考图未出现而删除。
- 桌面端项目列表优先使用三列紧凑布局；移动端回落单列。
- 背景构图需要同时提供可识别的主题图案和足够留白，使图案能透过玻璃但不影响文字。
- 参考图只决定视觉方向，不作为可替代真实项目数据的静态页面截图。

## 12. 多层模块的玻璃深度

Evidence、性能控制、架构说明等页面存在多层模块嵌套时，每一层都应体现半透明玻璃，但视觉强度随深度递减：

- 第一层：页面主容器，可使用轻量撕纸轮廓、`16–20px` 模糊和完整内高光。
- 第二层：主要章节与统计模块，使用 `9–13px` 模糊、较低不透明度和弱阴影。
- 第三层：指标卡、节点、表格行或说明块，使用 `5–8px` 模糊，只保留细内高光。
- 第四层及更深：不再继续增加模糊与阴影，改用透明分隔线、留白和文字层级，避免 GPU 负担与视觉浑浊。

深度规则：

1. 内层必须能看到外层的色调变化，不能重新变成不透明白卡。
2. 越深的层级阴影越弱，不能出现“层层悬浮”的厚重效果。
3. 表格表头允许稍深雾化，表体保持透明；Hover 只提高少量白色透明度。
4. 长文本区域优先保证对比度，必要时使用局部雾化而不是提高整层不透明度。
5. 不支持 `backdrop-filter` 时，所有层级必须降级为可读的高不透明度主题底色。
6. 多层玻璃仍需纳入响应式、页面错误、横向溢出和视觉回归 Gate。

## 13. CSS 级联与 Tailwind 优先级

本方向依赖自定义玻璃材质覆盖旧页面中的 `bg-white`、实心按钮和不透明模块底色。使用 Tailwind 时必须核对级联层级：

- Tailwind `utilities` 层可能覆盖写在 `@layer components` 中的玻璃背景，即使自定义选择器看起来更具体。
- 已包含大量旧工具类的页面，最终材质覆盖规则应放在 Tailwind 分层之外，或先移除冲突的背景和阴影工具类。
- 不能只检查源码中是否存在 `backdrop-filter`；必须读取浏览器最终 computed style 和实际截图。
- 导航选中态、模块底色、嵌套面板和降级样式都要确认最终生效，不能把未生效的 CSS 当作视觉完成。
- 后续重构可逐步把冲突工具类替换为语义组件类，再把样式安全地收回统一组件层。

## 14. Dashboard 最终参考结构

Dashboard 首屏必须完整遵循已确认样图的结构，而不是只借鉴配色：

1. 顶部为作者身份、中文主导航和印章式 GitHub 入口，不使用实心高亮按钮。
2. Hero 左对齐，展示中文标题、英文副标题和一句项目速览说明。
3. 项目矩阵紧接 Hero；桌面端三列，卡片保持统一紧凑高度。
4. 每张卡依次展示编号与状态、透明图标与摘要、架构概览、技术栈、进度和工作证明入口。
5. 第一屏未出现的原有简历、性能和完整 Evidence 内容下移保留，不得删除。
6. 项目排序优先展示 Agent Market、BabySteps、Shared Evidence Verifier、Personal AI Agent、Showcase Dashboard 和 TC Flow，其他真实项目继续顺序展示。
7. 样图只定义结构和材质，项目名称、状态、进度、技术栈与 Evidence 必须继续使用真实数据。

## 15. 批准样图的精确视觉合同

- 暖白宣纸、右上浪、中央远山和左下舟景是批准构图，不得替换成仅有相似气质的自由发挥背景。
- 背景必须是一幅连续完整画面，禁止通过 `repeat` 或 `repeat-y` 平铺，也禁止按整张长页面使用 `100% 100%` 拉伸。桌面按 `100% auto` 保持原始山水比例，图片结束后延续同色宣纸底；移动端固定背景高度并允许横向裁切。
- 玻璃必须继承当前位置的背景颜色：山、浪、纸纹应能自然透入玻璃；只叠加轻微乳白雾化、低饱和折射和边缘高光，不铺统一灰蓝或不透明白底。
- 桌面导航按批准结构实现：左侧姓名章与双行身份，中间红色亭台图形，右侧等宽的“作品集首页 / 项目 / 工作证明”文字导航和诚信章；选中态只使用细红色下划线。
- 左侧印章必须表达“徐天成”姓名篆刻；GitHub 外链不得伪装成诚信印章，应使用 GitHub 图形、账号名和外链提示形成独立的低透明玻璃入口。
- 项目卡内容顺序固定为“编号与状态 / 图标、标题、摘要 / 架构概览 / 技术栈 / 进度与工作证明”。标题使用稳重衬线体，正文使用高可读深蓝灰。
- 项目卡禁止固定高度挤压真实内容。使用 `min-height` 与同一网格行拉伸保持对齐；摘要最多三行、架构最多两行、技术标签允许两行。
- 状态占独立顶部区域，不通过标题右侧大块留白挤压长标题。视觉相似度不得以删除项目主页、Evidence、状态或技术信息为代价。

## 16. Dashboard 一级模块统一

- 撕纸玻璃不只用于项目卡。个人简历、性能观测及后续同等级 Dashboard 主模块都使用同一套一级撕纸玻璃容器。
- 一级模块允许撕纸轮廓、完整内高光和轻阴影；内部技能、指标、快照与说明块只使用平整低透明玻璃，不重复撕边。
- 背景山水颜色必须连续透过一级与二级玻璃，越深层透明度越高、阴影越弱；禁止内层重新变成不透明白卡。
- 撕纸轮廓不得裁掉标题、焦点环、操作入口或移动端内容；窄屏使用幅度更小、节点更少的轮廓。
